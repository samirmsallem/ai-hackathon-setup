# Spec-driven

**Idea:** Write and agree a specification and task list before any code; code is derived from the spec.

## Workflow
1. Fill `templates/specification.md` (agent drafts, team reviews).
2. Derive `tasks.md` from the spec.
3. Implement tasks in order, ticking them off.
4. Update the spec when reality differs; log why.

## Suggested agents / skills
Agents: architect, developer, reviewer. Frameworks: OpenSpec, GitHub Spec Kit.

## Checkpoints (for Supervised autonomy)
After spec approval; after task list; after each task group.

## Watch out for
Spec growing beyond 2 pages. Cap it; the acceptance criteria already exist in `challenge/`.

## Document in METHOD_LOG
What you changed from this recipe and why.
