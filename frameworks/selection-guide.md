# Selection guide

| Choice | Suitable for | Risk in the hackathon |
| --- | --- | --- |
| Native Claude Code / Copilot | Minimalist, Multi-agent | Low |
| Matt Pocock Skills | Skills-based, Hybrid | Low |
| Superpowers | TDD, planning, review | Medium |
| OpenSpec | Lightweight spec-driven | Low to medium |
| GitHub Spec Kit | Structured spec-driven development | Medium |
| GSD | Context engineering | Medium |
| BMAD Method | Full role-based delivery methodology | High |

Other combinations are allowed but flagged "unusual combination". The table is mirrored in `catalog.yaml` (`suitableFor`, `risk`).

| If your team wants to learn about ... | Consider |
| --- | --- |
| Baseline without tooling | Native only + Minimalist |
| Short, sharp alignment before coding | Matt Pocock Skills + Skills-based or Test-driven |
| Structured spec-first work | OpenSpec (light) or GitHub Spec Kit (fuller) + Spec-driven |
| Role separation and review | Superpowers or native agents + Multi-agent |
| Long-running context hygiene | GSD or Context-engineered (native) |
| Full agile ceremony | BMAD Method (reduced path only) |

Time guidance for 120 min: framework setup should stay under 10 min; if the framework wants more than 20 min of planning before code, use its lightest path.
Avoid stacking more than two frameworks; you will not be able to attribute results to a cause.
